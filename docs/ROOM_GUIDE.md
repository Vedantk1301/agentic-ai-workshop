# Teaching a large beginner room

Plan for 100-200 students with mixed Python familiarity. The presenter leads from the front; request 4-6 technical volunteers for seating zones. Students use individual devices where available, with optional sharing and keyboard turns. No individual laptop approval queue.

## Four common build checkpoints

1. A normal find_food(80) call returns the Rs 60 sandwich.
2. The new my_agent.py requests a tool and receives a result.
3. A student-added hours tool answers the combined question.
4. An actual local MCP discovery/call succeeds where setup permits.

At each pause ask for a room signal: ready, need help, or following a checkpoint/output. Address common errors from the front; volunteers help isolated issues. The normal route starts with a new learner file. Finished reference files are recovery checkpoints, and saved outputs are labelled observations of another run.

## Protect the main activity

The first agent build and second tool are the central hands-on result. LangGraph's single branch and the two-agent CrewAI handoff can be instructor demonstrations. Preserve the five-minute break and closing Q&A. If behind, cut the A2A/orchestrator teasers first, then shorten the team demonstration. Do not replace the first build with a long review exercise.

## Prepare before students arrive

Distribute the tested ZIP and exact setup instructions in advance. Confirm Wi-Fi, power, projector readability, laptops and volunteers. A private GitHub link alone does not grant access. Install core dependencies before class; avoid installing three frameworks or creating 100 accounts together.

Privately rehearse the exact live model and keep keys off screen. Local functions/MCP need no LLM key; a live agent does. Pairing, checkpoints, saved live recordings or labelled scripted rehearsal can support blocked students. Ask what they actually ran. Never describe a replay as a successful local live run.

## Slides and editor

Use slides to ask the next question, then switch to the editor for the short build. Keep the relevant slide visible during student typing. Presenter notes and slides/Live Run Sheet.md specify each switch, command and time. Use a large terminal/editor font and close private configuration tabs before projecting.
